Does the ASE pipeline actually work?

A four-tier calibration audit of the two-channel hapmixQTL association test — asking not whether the code computes its formula, but whether the p-values it produces are valid.

The default tau_mode='zero' is anticonservative — severely so on realistic data. The fix already exists in the codebase.

tau_mode='estimate' restores calibration in every condition tested, at no meaningful cost in power. It should become the default.

§1 Why this was needed

The existing suite (tests/test_hapmixqtl.py, ~35 tests) is almost entirely internal consistency — "does the code compute the formula we wrote" — plus recovery — "can it find a planted causal variant."

Neither class of test can detect an invalid error rate. A method can pass all 35 while producing p-values wrong by two orders of magnitude. That is precisely what was happening. It is also the same failure mode the knockoff work hit: green formula tests and green power tests, masking broken calibration.

Three structural facts that shaped the design

F1

tau_mode='zero' is the default, so weights are w = 1/v_inf. With the known-variance GLS SE (Var(β) = 1/xx, no estimated dispersion), the model asserts Gibbs inferential variance is the only source of error variance. hapmixqtl.py:467, 722

F2

Cat (the a–t inferential covariance) is computed and read from disk, but the channels are combined by scalar inverse-variance meta-analysis, which assumes independence. hapmixqtl.py:288–310

F3

p-values use a t reference for what is by construction a known-variance z. Minor and conservative at large N. hapmixqtl.py:698–705

§2 Null calibration

ρ had no detectable effect at any σbio. F2's prediction did not materialize — §3 explains why.

§3 Is ignoring Cat actually safe?

Rather than infer this from type-I error, measure the quantity the scalar meta-analysis literally assumes is zero: the correlation between the two channels' slope estimators, across 1,500 null replicates.

Ignoring Cat is safe, and there is a clean mechanism. Even with the underlying a–t noise correlated at ρ = 0.9, the slope estimators stay uncorrelated — every CI covers zero. The reason is the last column: the ASE predictor s (signed het indicator) is orthogonal to the total predictor g/2, because phase is random with respect to expression, so E[s | g=1] = 0. The channels project the correlated noise onto orthogonal directions and the correlation never reaches the combined estimate.

This retires F2: Cat is genuinely unnecessary for the current statistic — a design property to document, not a latent bug. Caveat: the argument depends on phase being random w.r.t. expression. Systematic, expression-correlated phasing error would break the orthogonality, and that is untested.

§5 Does two-channel beat total-only?

Each method's threshold is calibrated on its own null distribution, then power compared at matched empirical type-I error. This is the only fair comparison when one arm may be anticonservative — on a matched nominal threshold an anticonservative method always "wins" for the wrong reason.

§6 The realistic case

The most realistic tier: simulate allele-level negative-binomial counts, emulate a quantifier posterior by multinomial resampling, and feed the real compute_summaries_from_gibbs — so Va, Vt, Cat and all κ-pseudocount behaviour come from production code rather than from assumption.

Under the default, essentially every null test is significant — λGC is infinite because p-values underflow to zero. The mechanism is F1, and it is worse here than in §2 for a structural reason: a quantifier's posterior variance captures only allelic-assignment uncertainty conditional on the observed total. It contains neither the counts' own sampling variance nor biological variance. So v_inf understates true error variance by a large factor, the weights blow up, and Var(β) = 1/xx collapses toward zero.

Because this is the regime real Salmon/mmseq input actually occupies, tau_mode='zero' should be treated as invalid for real data, not merely imprecise. Note too that corr(a,t) ≈ 0.000 straight from the production path independently confirms §3.

§7 Benchmarked against published methods

Every tier above simulates from hapmixQTL's own assumed model — circular, since simulator and estimator share a worldview. This section removes that by generating from the model the ASE field actually uses, and which hapmixQTL does not assume: negative-binomial total counts with library-size offsets plus beta-binomial allele-specific counts, the structure behind TReCASE and RASQUAL. Three comparator tests are implemented directly — TReC-only (NB GLM), ASE-only (beta-binomial), and TReCASE (joint likelihood sharing one κ) — all by likelihood ratio.

1. Fixed hapmixQTL is statistically equivalent to TReCASE. On TReCASE's home turf it matches the published joint likelihood at every effect size (0.268 vs 0.274, 0.762 vs 0.760, 0.998 vs 0.998), while beating total-count-only by 3.7× at κ = 1.10. The premise survives external scrutiny, and §5's total-only comparison was not flattering itself.

2. The default does not merely invalidate p-values — it destroys the method's entire advantage. The tau='zero' row's uncorrected nominal power is 1.000 at every effect size, which looks spectacular. Thresholded on its own null it collapses to 0.094 / 0.194 / 0.462 — statistically indistinguishable from TReC-only, the very baseline the ASE channel exists to beat. That is the sharpest argument that this default is not worth keeping for compatibility: it is strictly worse than not using ASE at all. It is also a clean demonstration of why the matched-α methodology matters — on nominal p-values, the broken configuration is the best method in the table.

Scope: this reproduces the published model structure and implements the published tests; it is not a replication of either paper's exact parameter grid (PMC, Nature, bioRxiv and the asSeq docs were all unreachable from this environment). RASQUAL's additions over TReCASE — genotype uncertainty, mapping bias, sequencing error — are nuisance refinements on the same joint likelihood; the shared TReCASE core is what is implemented here.

§7b Where the bug came from

With the papers in hand, the design is no longer ours: mixQTL's allelic-fold-change grid, RASQUAL's sample sizes, and RASQUAL's metric — power at empirical FPR 10%, from a permuted null rather than a nominal threshold. That last choice is an independent endorsement of the matched-α methodology used throughout this report.

mixQTL's error terms (Liang et al. 2021, Eqs. 3–4) are ε_asc ~ N(0, σ²·(1/Y₁ + 1/Y₂)) and z̃ ~ N(0, σ̃₀²). The counts set only the shape of the weights — σ² and σ̃₀² are free scale parameters, and Supplementary Notes §5.2, titled "Inferring σ̃₀² and σ²", solves for both from the data.

hapmixQTL replaced that freely-scaled variance with the Gibbs v_inf treated as fully known — dropping the free scale entirely. That is exactly the tau_mode='zero' defect. The bug is a deviation from the parent method, and tau_mode='estimate' is a re-derivation of what mixQTL always did.

mixQTL's weight cap does not fix it. The +weight cap column is identical to tau='zero' at every sample size and effect size — same 20× type-I, same power. The cap bounds the ratio between weights, but hapmixQTL's failure is that all weights are uniformly too large, so capping the ratio changes nothing. The free scale parameter is the load-bearing part, not the guardrail.

The elaborate fix buys nothing either. A nested σ²·v_inf + τ model, containing both mixQTL's multiplicative scale and hapmixQTL's additive offset, does not beat plain additive τ (0.575 vs 0.615 at N = 100) and is marginally worse at larger N. The simple fix is the right one.

And tau='zero' tracks trcQTL almost exactly at matched FPR (0.495 vs 0.535 at N = 100, aFC 1.25) — confirming on the published design that the broken default discards the allele-specific channel entirely.

Consistency: RASQUAL reports real-data eQTL power of RASQUAL 42.2% > CHT 35.7% ≈ TReCASE 35.5% > Lm 25.7%. Our TReCASE numbers bracket their figures in the aFC 1.10–1.25 range where real eQTL effects sit, and the ordering reproduces. A point-to-point match is not meaningful because RASQUAL draws effect sizes from empirical real-data distributions. Expectation this sets: since fixed hapmixQTL ≈ TReCASE, and RASQUAL beats TReCASE by ~19% relative via genotype uncertainty, mapping bias and sequencing error, hapmixQTL should be expected to sit ~19% below RASQUAL on real data until it models those nuisance terms.

§7c The assumption nobody checks

Sun (2012) and its descendants let the two channels carry their own effect sizes and test whether they agree. In CSeQTL's notation (Little et al. 2023): η(A) = η(T)·α, and the effect is cis exactly when α = 1.

hapmixQTL's inverse-variance meta-analysis assumes α = 1 — that is the entire justification for putting both channels on a common log-aFC scale and averaging them — and it never tests it. When α ≠ 1 the meta-analysis averages two different estimands. And α ≠ 1 is not exotic: a trans component acting on total expression only, reference mapping bias attenuating the ASE channel, systematic phasing error, or feature-level misquantification all produce it.

Because §3 established the two slope estimators are uncorrelated, the difference has variance se_a² + se_t² with no covariance term, so a simple Wald test is valid — the same orthogonality that let us retire Cat is what makes this diagnostic cheap.

For a gene whose eQTL is not purely cis, hapmixQTL silently reports a badly attenuated effect. At α = 0 — a real total-expression effect with no allele-specific component, i.e. a trans-eQTL — it reports 0.076 instead of 0.400, an 81% attenuation, with no warning. At α = −0.5 the reported effect changes sign. The test catches these 92% and 100% of the time.

The honest limitation: detection power is weakest (11.6%) exactly where the bias is mildest but not negligible — α = 0.75 still attenuates by 20%. This is a screen for gross violations, not a guarantee of consistency. It also gives hapmixQTL something it currently cannot do at all: distinguish cis from trans eQTLs, a headline capability of the TReCASE family.

§7d Real data

Everything above is simulation. This is GTEx v8 haplotype-expression from phASER — genuine per-gene, per-sample yL | yR counts, which is exactly hapmixQTL's input. 400 genes × 706 Muscle-Skeletal samples, median allele-specific depth 54 reads.

GTEx genotypes are dbGaP-protected, so real cis-QTL mapping is not possible from public data. But the sharper check is available: real haplotype counts supply the real variance structure — genuine overdispersion, depth distribution, zero inflation, biological variability — and genotypes drawn independently of expression make every test a true null. Same logic as RASQUAL's permutation null.

§7e What it costs to run

RASQUAL reports cost as a headline result (539.9 CPU-days vs TReCASE 4.6 vs Lm 0.4), and mixQTL's whole framing is that joint likelihood methods are intractable at scale. hapmixQTL inherits that log-linear framing, so its cost is a claim worth measuring.

hapmixQTL is ~3,400× faster than TReCASE at statistically equivalent power. That is the trade the log-linear approximation buys — now measured rather than asserted, and the strongest argument for the method's existence alongside its calibration. The τ fix costs ~60% more than the broken default: negligible in absolute terms.

Caveat: our TReCASE is a Python/scipy reference implementation, not asSeq's optimized C, so 3,446× is an upper bound. Our 27.3 CPU-days against RASQUAL's published 4.6 for TReCASE suggests roughly a 6× implementation penalty; even correcting for it, hapmixQTL remains ~500× faster.

§7f Recovery and robustness

Four things that were open. Parameter recovery: the whole fix rests on _estimate_tau, and it recovers τ to within 0.4–1.3% relative bias; effect estimates are unbiased to ≤0.001 with corr(estimated, true) = 0.987. Covariates: the residualizer path is calibrated across 0–30 covariates (0.94–1.06×).

Phasing error — the §3 caveat, resolved favourably. §3 argued Cat is ignorable because s is orthogonal to g/2 under random phase, and flagged systematic phasing error as the untested threat. Flipping a fraction f of heterozygote phase calls: calibration survives entirely (λGC 0.97–1.09 even at f = 0.50), attenuation follows the textbook (1 − 2f) exactly, and corr(β_a, β_t) stays at zero throughout (+0.02 to +0.07). Phasing error costs power, not validity — and the orthogonality that retires Cat holds.

The τ defect corrupts variant-level localization, not just gene-level p-values. Under the old default a variant with PIP 0.98 was truly causal only 34% of the time, and a nominal 95% credible set contained the causal variant 36.8% of the time. It manufactured 432 credible sets where the calibrated fit finds 77 — most of them spurious.

This is the third independent consequence of one root cause, after invalid p-values (§2, §6, §7d) and 64.5% CI coverage (§4). Practical implication: any fine-mapping run under tau_mode='zero' should be treated as invalid and redone, not merely re-thresholded. With the fix, PIP calibration is near-perfect and credible-set coverage is 0.987 against a 0.95 target.

§7h hapmixQTL vs RASQUAL, measured

Earlier sections compared against TReCASE only and explicitly disclaimed implementing RASQUAL. This closes that gap by adding its two distinguishing features: the shared θ (their supplement derives both components from one gamma-Poisson process, so a single θ sets the NB shape and the beta-binomial precision, where TReCASE fits them separately), and the nuisance terms δ (sequencing error) and φ (reference bias).

The shared θ is real but small. It buys +0.012 over separate dispersions — consistent in direction across scenarios, but modest, matching RASQUAL's own framing of it as improving model stability rather than a large power claim. hapmixQTL's additive τ sits ~0.05 below the joint likelihoods at aFC 1.25 (≈7.5% relative) and is indistinguishable at aFC 1.10. Against §7e's ~3,400× speed advantage, that is the trade — a constant-factor cost, not a structural deficiency, and far smaller than the ~19% gap previously inferred.

But reference bias is not minor, and it is hapmixQTL's real exposure. At φ = 0.60, every method that does not model it breaks: nominal type-I error goes to 0.52–0.64, a 10–13× inflation, and power at matched FPR collapses to ~0. hapmixQTL is the worst affected (0.635). RASQUAL-like, which fits φ, is completely unaffected. The total-only channel is immune, as it must be — g/2 carries no allelic information to bias.

Reconciling this with "reference bias had a minor impact"

RASQUAL's ablation found removing φ cost nothing, and §7d found WASP correction made no difference on GTEx. Both were measured on data where the bias had already been removed upstream: RASQUAL estimated φ̂ as small at most loci in their own data, and GTEx's phASER matrices explicitly exclude sites in low-mappability regions or showing simulated mapping bias — §7d compared two already-filtered matrices.

So: reference bias is minor in practice only because pipelines filter it out beforehand. RASQUAL carries an internal defence and degrades gracefully when filtering is imperfect; hapmixQTL has none and fails catastrophically rather than gradually. Its validity is contingent on upstream mapping-bias filtering in a way §7d could not reveal, because that section only compared two clean inputs.

§8 Recommendations

  1. Change the default to tau_mode='estimate' in map_nominal, map_cis and map_susie. One line per call site, and the single highest-value fix identified. Left as a separate decision here because it changes published behaviour.
  2. Warn or refuse on tau_mode='zero'. If kept for backward compatibility it should warn loudly: it is valid only when inferential variance is provably the entire error variance, which real quantifier posteriors never satisfy.
  3. Document Cat as intentionally unused, with the orthogonality argument from §3, so a future reader neither mistakes it for an oversight nor silently "fixes" it.
  4. Add a calibration gate to CI — the control cell plus one inflated cell, as a fast test, would have caught this immediately.
  5. Document the mapping-bias precondition and add a φ diagnostic (§7h). hapmixQTL requires mapping-bias-filtered input — a hard precondition, not a suggestion. A cheap detector: the pooled allelic ratio at heterozygotes across genes should sit at 0.5; a systematic departure flags the failure before it silently inflates every p-value. Fitting φ outright is the single highest-value remaining feature.
  6. Ship the cis/trans test (§7c) as a per-gene diagnostic column. It is ~10 lines given what calculate_hapmixqtl_nominal already returns, it validates the assumption the meta-analysis rests on, and it adds cis-vs-trans classification. Genes failing it should be flagged, not silently reported with an attenuated effect.

§9 What remains untested

  • Phasing error. §3's orthogonality argument assumes phase is random w.r.t. expression; systematic expression-correlated phasing error would break it.
  • Real ASE data. Every tier here is simulation. The strongest real-data check needs no external truth: because the total channel uses g/2, both channels estimate the same quantity, so regressing slope_a on slope_tc across real variants should give slope 1. Blocked on real allele-count + Gibbs input.
  • Covariates. All tiers run without covariates; the residualizer path is unit-tested but not calibration-swept.
  • Robust SEs. se_mode='robust' may be self-correcting for F1; untested here.
